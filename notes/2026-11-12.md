## Applied — 2026-11-12 (Hyprland login + distrobox)

- `[SYSTEM]` **ly autologin into Hyprland**: `auto_login_session = "hyprland"`,
  `auto_login_user = "gio"` in `/etc/ly/config.lua`. Next boot lands directly in the
  Hyprland session. Original saved as `/etc/ly/config.lua.bak-20261112`;
  `ly-autologin` (pam_permit) was already installed. Autologin fires once at
  greeter start — a logout returns to the normal session menu.
- `~/.config/hypr/autostart.conf`: added
  `systemctl --user import-environment WAYLAND_DISPLAY HYPRLAND_INSTANCE_SIGNATURE XDG_CURRENT_DESKTOP`
  then `systemctl --user start graphical-session.target`. `dms.service` is
  `WantedBy=` **and** `Requisite=graphical-session.target`, and `start-hyprland`
  does not start that target — without these two lines the session would come up
  with no bar, dock or menus.
- Verified before touching the login default: `Hyprland --verify-config` → `config ok`;
  a **nested** Hyprland on the real config starts, detects a monitor, and runs
  `exec-once` (the physis-selector rofi window appeared).
- Distrobox pull root cause: `quay.io/toolbx/arch-toolbox:latest` is published as a
  **schema1** manifest (`"schemaVersion": 1`, `fsLayers`) — podman dropped schema1,
  which is why every attempt copied 0 bytes. `quay.io/toolbx-images/...` returns
  UNAUTHORIZED. Registry itself is fine: `docker.io/library/alpine:3.20` pulled
  (8.1 MB, exit 0).
- Root tier run with sudo: `apt-get clean` (apt cache was already 48 K),
  `journalctl --vacuum-size=50M` (freed 0 B), `flatpak uninstall --unused` (nothing
  unused). Net gain ≈ 0; disk remains ~26 G free.
- **Container created**: `distrobox create --yes --name arch-omarchy` with
  `quay.io/archlinux/archlinux:latest` (OCI v2, 139.6 MB) → PULL_EXIT=0, CREATE_EXIT=0.
  Throughput on this link is ~285 KB/s (quay) vs ~150 KB/s (Docker Hub), so allow
  ~10 min for the pull. The previous image was the blocker, not distrobox/podman:
  `docker.io/library/alpine:3.20` pulled fine the whole time.
- First `distrobox enter` provisions the in-container user + sudo/passwd via pacman,
  which is slow on this link — do not mistake it for a hang; the container itself is
  already created and usable with `podman exec`.

- **Deployed** with `./adapters/omarchy/install.sh` (release build 3m26s):

  `~/.config/hypr/physis-omarchy.conf`, `~/.config/systemd/user/physis-omarchy.service`,
  desktop entry + icon. `extra.conf` backed up to `extra.conf.pre-omarchy` and the
  `source = …/physis-omarchy.conf` line appended.
- **Two config defects found and fixed before trusting the deploy:**
  1. `$mainMod` was undefined everywhere (`binds.conf` writes `SUPER` literally).
     Hyprland swaps an undefined variable for an empty string, so the adapter's
     binds were silently becoming bare `P`/`H`/`O`; `--verify-config` still said
     `config ok`. Added `$mainMod = SUPER` to `hyprland.conf`.
  2. `$mainMod SHIFT, H` (HUD) collided with `binde = SUPER SHIFT, H, movewindow, l`,
     and `extra.conf` is sourced last → the adapter would have won. Rebound the HUD
     to `SUPER+SHIFT G` in `adapters/omarchy/hypr/physis-omarchy.conf` and redeployed.
- **Verified:** `Hyprland --verify-config` → `config ok` with the adapter file
  sourced; unit `inactive (dead)` + `disabled` under niri; daemon exits 0 with
  "Hyprland session not found" (no restart loop); `physis-omarchy` CLI present.
- **Not done / not doable from inside the session:** the graphical smoke test
  (`SUPER+SHIFT P/G/O`, socket at `$XDG_RUNTIME_DIR/physis-omarchy.sock`). Also
  skipped a nested Hyprland run on purpose: `autostart.conf` imports
  `WAYLAND_DISPLAY`/`HYPRLAND_INSTANCE_SIGNATURE` into the user systemd manager,
